# 学术文风：按 academic-humanizer 的逻辑改稿

> **逻辑来源**：[AIScientists-Dev/academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer)
> （MIT License，Copyright © 2026 AIScientists-Dev）。上游定位是
> *strip AI-writing tells from papers and grant proposals (NSF/NIH), while keeping scholarly voice and
> tying claims to evidence*，作为 Claude Code / Codex / MorphMind 的 skill 分发，被多家媒体（含
> Nature 相关报道）讨论过。它又基于 [blader/humanizer](https://github.com/blader/humanizer)（MIT）
> 与 ARMS 的标准，一并致谢。
>
> 本文件是该逻辑的**中文适配**：保留分层结构、判断标准与四步流程，例子换成中文学术常见句式，
> 并补上中文特有的 AI 痕迹词。**本 skill 不再使用自研的"三轴"规则。**

## 核心原则

学术写作本来就有"对人的声音"：中性、精确、第三人称（或"本文/我们"），
并且**每一条主张都系在它的证据上**。所以改稿只做两件事：

1. **剥掉 AI 痕迹**，但不把文章口语化；
2. **执行一条纪律**：每个主张都要挣得自己的数字、图或引用；**没有动词可以强过它的证据**。

它**不改**任何数字、结果、引用；也**不是**用来规避 AI 使用披露的工具。

## 四步流程

| 步骤 | 做什么 | 不做什么 |
|---|---|---|
| **Read** | 通读，认出文体（期刊论文 / 学位论文 / 基金本子）与目标场合 | 不急着改 |
| **Audit** | 逐条列出命中模式与位置，以及每条实证主张的证据状态 | 不动笔 |
| **Rewrite** | 结构、内容、主张、引用全部保留；去痕迹、把过强的话降到证据水平 | 不新增或删除论点 |
| **Report** | 交回正文 + 简短改动清单（删了什么、哪句补了证据、语体说明） | 不隐瞒改动 |

`ai_tone_check.py --audit` 输出的就是 Audit 清单（层 / 编号 / 类型 / 位置 / 改法）。

## Layer 1 通用 AI 痕迹

病根：**用姿态、规则、权威、模板代替具体信息**。

| 编号 | 痕迹 | 中文常见形态 | 怎么改 |
|---|---|---|---|
| T1.1 | 意义拔高 | "标志着……的重要转折""具有重要的理论意义""奠定了坚实基础" | 写清它约束了什么、改变了哪个结论 |
| T1.2 | 假深度的尾巴 | "……，凸显了其独特价值" | 删掉，或换成具体结论 |
| T1.3 | 宣传化用词 | 赋能、助力、深耕、闭环、抓手、颠覆、革命性 | 换中性词：赋能→支持，助力→帮助，闭环→反馈机制 |
| T1.4 | 无来源的权威 | "专家认为""研究表明"（后面没有引用编号） | 补引用；给不出就删 |
| T1.5 | AI 高频空词 | 深入探讨、全方位、全链路、极大地 | 换成具体动作与对象 |
| T1.6 | 回避系动词 | "作为……的重要组成部分""扮演着重要角色" | 直接写"是/属于" |
| T1.7 | 否定式排比 | "不仅是……更是……""不是……而是……" | 除非真在纠正误解，否则直接陈述 |
| T1.8 | 三项式凑数 | "快速、准确、稳定" | 留一两个可测的，其余删 |
| T1.9 | 同义反复换词 | "换言之""换句话说" | 一个概念全文用一个词 |
| T1.10 | 填充套话 | 值得注意的是、众所周知、不言而喻 | 直接删 |
| T1.11 | 长句堆砌 | 一句话挂 3 个以上长分句 | 一句话一个判断，拆开 |
| T1.12 | 破折号 | "——……——" | 改用逗号、冒号、括号或另起一句 |

## Layer 2 学术 AI 痕迹（2.1–2.11）

### 2.1 过度断言动词
实证工作"显示/提供了证据"，不"证明"普遍真理。
**盯**：证明、证实、确保、保证、彻底解决；没有检验和数字的"显著"。
> 改前：本文证明了本方法显著优于所有先前方法。
> 改后：在三个留出集上，本方法比最强基线高 3—6 个百分点（表 3），配对检验 p<0.01。

### 2.2 显著性炒作
**盯**：开辟新范式、为……铺平道路、有望彻底改变、填补空白、重大突破。
> 改前：本研究为新的范式铺平了道路。
> 改后：本研究处理先前方法的一个失效模式：长时程推演下的误差累积（第 4 节）。

### 2.3 空泛强化词
**盯**：广泛的实验、全面的评估、大量数据、多种场景。
> 改前：我们在大量数据上做了广泛实验。
> 改后：我们在 3 个数据集（ImageNet、CIFAR-100、iNaturalist）上评估。

### 2.4 新颖性填充
**盯**："首次""据我们所知""填补空白"；"新颖"一节出现多次。
> 改前：据我们所知，本文首次研究该问题。
> 改后：本文研究延迟标签下的在线校准，这是离线校准工作未覆盖的情形。

### 2.5 模板化开头
**盯**："随着……的快速发展""近年来……受到广泛关注""尽管已有进展……"。
> 改前：随着图学习的快速发展，表格数据建模受到广泛关注。
> 改后：表格模型有一个结构性缺陷：多数模型丢弃特征类型元数据，只能从数据里重学。

### 2.6 连接词连用
连续几句用"此外/同时/另外"开头会读成清单；让逻辑自己承接。

### 2.7 贡献清单套话
**盯**："本文贡献如下：首先……其次……最后……"，每条都是摘要复述。
> 改后：每条贡献写成一个具体结果（指标 + 对比 + 条件）。

### 2.8 文献堆砌
**盯**："许多方法已被提出 [3,7,9,12,15]"。
> 改后：最接近的是 TabNet[7]，它联合编码全部特征；本文改为以特征类型元数据为条件。

### 2.9 模糊限定
**盯**：较为、一定程度上、相对来说、比较好。
> 改前：性能稍好且相对稳定。
> 改后：准确率高 3 个百分点，5 个随机种子上波动小于 1 个百分点。

### 2.10 强调套话
**盯**："值得注意的是""需要强调的是""尤其要注意"。若真重要，句子本身会显示出来。

### 2.11 从句堆叠
AI 偏爱用逗号和"其/该/这"串三四个从句。拆开，一句话一个判断。

## Layer 3 这些必须保留（不许过度修改）

通用去 AI 味工具会把合法的学术写法一起抹平。以下保留：

| 保留项 | 说明 |
|---|---|
| **有证据的模糊限制** | "提示""与……一致""我们假设""可能"——确实不确定时**必须**保留。把 "results suggest X" 改成 "prove X" 是制造过度断言 |
| **被动语态** | 施动者无关时正确：*Samples were normalized to total protein.* |
| **第一人称复数** | "我们/本文"是标准写法，不必为避讳改写 |
| **分号、适度三项式** | 可保留；破折号例外（T1.12，改掉） |
| **术语、方法名、指标名、公式、符号** | 原样保留 |
| **数字、方程、引用** | **绝不许编造、删除或改动**；引用键一个都不能少 |

脚本把这条做进了代码：句中带数字时 T2.1/T2.2/T2.3/T2.9/C1 不报；C 类规则遇到
"证据型模糊限制 + 数据/图表/引用"也不报。

## Layer 4 主张-证据纪律

对每条实证主张问两件事：**(a) 有没有数字、图、表或引用支撑？(b) 动词强度与证据匹配吗？**

| 情况 | 处理 | 编号 |
|---|---|---|
| 主张没证据指针 | 补"[图 3]""[表 2]""[12]"，或降调 | C1 |
| 量级模糊（"提升不少"） | 换成区间并说明统计口径 | C2 |
| 比较对象缺失（"优于现有方法"） | 指明哪个基线、哪个指标、差多少 | C3 |
| 结论强于设计（"可广泛应用于各类场景"） | 写成实测条件；"所有/任何"通常没证据 | C4 |

三条细则：**优先给区间**（除非已说明平均方式）；每个数字能追到"方法 + 指标 + 基线"；
比较时**先跟最强竞争者比**，不是跟弱基线比。

> 改前：本方法更鲁棒。
> 改后：分布偏移下本方法准确率下降 2 个百分点，基线下降 11 个百分点（图 3）。

## Layer 5 语体与场合匹配

作者给过既往论文就照着它的节奏改（句长、连接习惯、限定位置、开篇方式、记号）；
没有样本时默认**干净、精确、符合刊物语体**，不要写成随笔腔。
场合差异：ICLR/NeurIPS 类简洁直接、结果前置；Nature/PNAS 类更多阐述。
**绝不**往论文里注入观点、幽默或第一人称"个性"——对技术写作，中性精确就是人的声音。

## Layer 6 基金本子模式（NSF / NIH）

本子不是论文，靠**愿景 + 可行性**取胜，评审从第一页给分，所以规则不同：
**不要把愿景削平**，改查另一条纪律——**主张 ↔ 可行性**。

### 6.1 结构与重点

- **NSF**：1 页 Project Summary，三段对应评审标准（Overview / Intellectual Merit /
  Broader Impacts），各自独立成立；Project Description 开头 1—2 页交代
  "长期愿景 → 本申请目标 → 缺口 → 具体 thrust → 回报"。
- **NIH（R01）**：**Specific Aims 一页就是整份申请**，最常被读、最决定成败。
  弧线：问题与已知 → **缺口/关键需求** → **长期目标 + 中心假设（附依据）** →
  "The objective of this application is…" → **2—3 个 Aim**（一句话目标 + 做法 + 预期结果）→
  **回报段**：成功之后什么会改变。

### 6.2 前三页定生死

到第 1 页（NIH Aims）或第 2—3 页（NSF）结束时，读者必须已拿到：钩子（为什么具体重要）、
缺口（缺什么、代价是什么）、中心思想（一句话做法）、aims/thrusts（清晰且平行）、
回报（payoff）。缺哪个先补哪个，再谈后面章节。

### 6.3 本子特有的弱招

| 弱招 | 改法 |
|---|---|
| 空泛重要性（"非常重要且及时"） | 写具体缺口与代价 |
| 方法当目标（"Aim 2：把迁移学习用到数据集上"） | 改成问题/结果导向（"Aim 2：判断融合可穿戴与实验室信号能否改善早期识别，对哪些亚组有益或有害"） |
| 多米诺 aims（Aim 2 依赖 1） | 改成平行、各自有价值；确有依赖时写明兜底方案 |
| 有雄心无可行性 | 每条大胆主张旁边挂证据：前期数据、已完成工作、经典定理、合作者 |
| 模板化 Broader Impacts | 具体、可枚举、与研究绑定：项目名、课程、工具、可测的 outreach |
| 中心假设含糊（"我们将探索是否可能……"） | 中心假设是可证伪的承诺；校准的模糊留给 Approach 的解释 |

### 6.4 要保留甚至加强的（本子的手艺）

- **愿景/雄心开篇**：大胆的长期目标，本申请只是其中一步；
- **可扫读的引导词**：**Goal:** / **Motivation:** / **Innovation:** / *Aim N（一句话使命）*；
- **贯穿的实例/主角**：让抽象方法在各 aim 中保持一致；
- **把挑战写成问题**：一个清晰的开放问题读起来像"定义良好的问题"；
- **锚定经典结果**：引用已知不等式、容量概念、检验，显示谱系与严谨；
- **把团队记录当可行性证据**：前期结果、已获资助、发表、合作方**放前面**。
  ——只能用作者真实提供的记录，**绝不编造**资助、结果、伙伴或推荐信。

### 6.5 主张 ↔ 可行性（本子的 Layer 4）

对每个 aim 与承诺检查：雄心有没有对应手段（前期数据、既有方法、经典基础、合作者、分阶段降险）？
有 → 保留强动词；没有 → 补证据，或把主张降到计划能支撑的水平。
**永远不要编造前期结果、资助、伙伴或推荐信**；支撑不存在时明确标出来让作者补。

## 交稿格式

返回**改后正文 + 简短改动清单**：删掉了哪些模式（按类型）、哪些主张被降调或补了证据指针、
语体/场合说明；并确认**没有改动任何数字、公式或引用**。

## 与脚本的对应

`scripts/ai_tone_check.py` 实现本文件里**可枚举**的部分（词典 + 正则 + 句长/连接词/数字密度），
输出两个分数：

| 分数 | 含义 | 对应层 |
|---|---|---|
| `tells_score` | AI 痕迹密度 | Layer 1 + Layer 2 |
| `claims_score` | 主张强于证据的程度 | Layer 4 |

两者都低才算合格。它只负责 **Audit**（报警 + 定位 + 改法），**不替你改稿**，
也**不判断**"是不是 AI 写的"：分数高不等于 AI 写的（模板化公文、翻译腔同样高分），
分数低也不等于合格（真问题常在论证与数据）。

基金本子模式（Layer 6）**不在脚本里**——它需要逐个 aim 判断可行性，属于人或 agent 的活。
